# Rendered room 1

Open `Assets/_Project/Scenes/RenderedRoom.unity` in Unity **6000.6.7f1** and press Play. This is the first enabled build scene; `TestRoom` remains available. The existing XRI Starter Assets rig supplies tracked walking, controller locomotion, snap turning, teleportation, and near/far interaction. The included XR Device Simulator supports desktop inspection.

The coffee table contains exactly one pickable: the existing `mug.prefab` from PR #1. The scene instance is fitted to 10 cm in height, with its collider fitted to the mesh, continuous physics collision, interpolation, and dynamic grab attachment. Other furniture is static. The mug prefab source remains unchanged. Its original low-poly mesh is retained, with a warm ceramic URP material on this scene instance.

## Rebuilding

From the repository root:

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b -t 8 -P tools/room/build_room.py
/Applications/Unity/Hub/Editor/6000.6.7f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -quit -projectPath "$PWD" \
  -executeMethod RoomVR.EditorTools.BuildRenderedRoom.Run \
  -logFile /tmp/rendered-room.log
```

Alternatively run **RoomVR → Build Rendered Room** after the Blender export. This deliberately replaces only `RenderedRoom.unity` and its generated materials, and puts the scene first in build settings. Save hand edits elsewhere before rebuilding.

`tools/room/RenderedRoom.blend` is the editable Blender source. It is outside `Assets` so Unity does not invoke Blender on import. Original room geometry and procedural materials are generated by `build_room.py`; no downloaded room models or textures are required. Blender exports FBX geometry and radiance textures under `Assets/_Project/Models/RenderedRoom`. All binaries use the repository's Git LFS rules.

## Rendering approach and limits

The supplied photograph guides furniture placement, ivory/sage textiles, oak, a tall blind-covered window and warm lighting. Dimensions (4.2 × 5.6 × 3.5 m) and unseen surfaces are inferred from a single image. This is a modeled interpretation, not a measured reconstruction or a claim of photographic equivalence.

Cycles bakes static materials, indirect illumination and shadows into a 4096 px furniture atlas and 2048 px architecture atlas. Unity uses URP Unlit for this static radiance and a lit shader for the movable mug. The wall/ceiling geometry and material remain separate and tintable. Changing the wall tint in Unity also tints its baked illumination; major material or lighting changes should be rebaked in Blender. Static furniture must not be moved without rebaking.

This keeps runtime lighting inexpensive, but baked surfaces do not receive a changing shadow from the movable mug. There is no runtime GI or parallax trick: geometry is fully three-dimensional and viewable while walking. Furniture and room boundaries have independent collision proxies; the floor uses the existing rig's teleport interaction layer (bit 31). The doorway is visually open but has a boundary collider, keeping the player within the modeled room.

`docs/room-blender.png` is the source render (without the separately instantiated mug); `docs/room-baked-blender.png` shows the baked atlas version before Unity import. `docs/room-unity.png` is captured by a real Unity camera, including the mug. The preview camera is disabled during play; the XR rig camera renders the experience.

Physical Quest controller acceptance and headset frame timing require device testing. No measured headset performance or APK validation is implied by desktop checks.

## Verification (November 7, 2026)

Unity 6000.6.7f1 on macOS: **8/8 EditMode** and **2/2 PlayMode** tests passed. Checks cover prefab identity and 10 cm dimensions, fitted mug collider, shader/texture presence, separate architecture, correct teleport layer, no missing scripts, build inclusion, and agreement between the visible table vertices and the physical tabletop. PlayMode exercises walking from the entrance toward the table, boundary collision, and actual XR selection → lift → release → physical settling on the table.

The generated scene contains 171,395 mesh triangles including the rig's visible meshes and the mug. This is an editor geometry count, not a device performance measurement. The static room is two mesh renderers using baked radiance textures. Desktop tests use an automated interactor and character-controller movement; physical controller bindings and headset comfort still need acceptance on Quest.

Visual acceptance remains incomplete: the baked bedding and some upholstery edges retain visible atlas artifacts, and the furnishings are simpler than the supplied photograph. The current scene is a functional, photo-inspired reconstruction; it does not yet match the reference's photorealistic quality.
